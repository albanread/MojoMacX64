# Divergences from the MojoCocoa tree that are ALLOWED, with their reason.
#
# One line per entry: <path>|<symbol-or-WHOLEFILE>|<sha256-16 of OUR version>|<reason>
#
# The hash makes the allowlist a TWO-SIDED contract: the symbol may differ from
# upstream, and it may not change here without someone deliberately updating
# this file. Without it an allowlisted symbol is an unguarded hole -- which is
# exactly where our most ABI-critical code lives.
#
# Nothing lands here without evidence -- clang's own output, the cocoa.sqlite
# tables, or a measurement on this hardware. An entry is a promise that the
# difference is required by x86-64, not that it was convenient. See
# PARITY_SPRINT.md.

KGEN/lib/CocoaKB/CocoaKBDatabase.cpp|WHOLEFILE|-|every ABI query reads the _x64 tables; theirs reads the arm64 ones. Enforced by property instead of by diff: see check-parity.sh
KGEN/lib/CocoaKB/CocoaKBDatabase.cpp|kSelectorVariantSQL|-|same divergence as kMsgSendVariantSQL, selector-keyed
KGEN/lib/CocoaKB/CocoaKBDatabase.cpp|kMsgSendVariantSQL|-|upstream hard-codes 'objc_msgSend' because arm64 has exactly one send; x86-64 has three, and 3670 SDK methods need _stret and 2 need _fpret. Answering the constant reads results from registers never written
spikes/s5-cocoakb/check.mojo|WHOLEFILE|-|the dispatch assertions invert by architecture: theirs asserts -[NSValue rectValue] -> objc_msgSend with return class h4 (a 32-byte CGRect is a Homogeneous Float Aggregate in v0-v3); ours asserts objc_msgSend_stret with return class s (SysV MEMORY). Both are correct on their own machine and neither can hold on the other
spikes/s5-cocoakb/stret_test.mojo|WHOLEFILE|-|same inversion, and their own header says so: "Filename kept to match the sister x86-64 fork; there is no stret on arm64"
spikes/s5-cocoakb/abi_oracle.c|-|-|ours is spikes/abi-oracle/abi_oracle.m -- ported IN SHAPE from theirs with the cases replaced, which is required rather than preferred: theirs exercises AAPCS64 (indirect args, HFA in v0-v3, sret via x8) and ours exercises SysV (stack args, objc_msgSend_stret, objc_msgSend_fpret). The last two entry points do not exist on arm64, so there is nothing to share. Objective-C (.m) rather than C because ours defines real classes to message. See spikes/abi-oracle/README.md
